# 혜택 수집 설계

> 작성일: 2026-09-26. 혜택(지원·장학금·강좌·훈련·체험·대회·자료)을 **효율적으로 모으고 최신으로 유지하는** 방법이다.
> 근거: ① 공식 데이터 경로 조사(웹 조사, 항목마다 확인됨/추측/확인 못함), ② 같은 팀이 만든 [korea-ai-contest-tracker](https://github.com/Sweet-Butters/korea-ai-contest-tracker)(공모전 레이더)에서 가져온 장점.
> 관련 결정: D5(수작업 먼저), D8(지도), D17(당근: 지원 추천 자동 갱신), D22(혜택이 노선도 옆에 자동으로). 데이터 형식은 `data/schema/help.schema.json`.

## 0. 한 줄 요약

**공공데이터포털(data.go.kr) 인증키 하나로 대부분을 공식 API에서 받고**, 공모전 레이더의 파이프라인(매일 GitHub Actions, 출처별 모듈, 규칙 먼저 + AI 보조, 중복 합치기, 출처별 건강 기록, 정확도 평가)을 그대로 가져온다. 민간 공모전 사이트는 재게시하지 않고, 공식 피드가 없는 곳(꿈드림, 교육청, 지자체)만 사람이 모은다.

## 2. 공모전 레이더에서 가져오는 것

| 공모전 레이더의 장점 | 여기서는 |
|---|---|
| 서버 없이 **매일 GitHub Actions**가 모으고 JSON을 커밋 | 그대로. 매일 06:00 KST, 결과는 `data/collected/`에 커밋 |
| **출처별 모듈**, 한 곳이 고장 나도 나머지는 돈다 | `crawler/sources/<name>.py` 하나씩. 같은 `fetch()` 모양 |
| 실행마다 **출처별 건강 기록** (가져온 수, 남긴 수, 오류, 초) | `data/collected/meta.json`. 관리 화면에 보여 준다 |
| **robots.txt를 매번 확인**, 사이트별 속도 제한, 자기 이름을 밝히는 User-Agent | 그대로. API가 아닌 곳에만 해당 |
| **규칙이 먼저, AI는 확신할 때만** 뒤집는다. 답을 캐시해 새 항목만 보낸다. 비용·지연을 매 실행 기록 | 대상·분야 판정에 그대로 (4절) |
| 사이트끼리 **같은 항목을 합친다** (이름 정규화 + 같은 마감일) | 사업명·소관기관 정규화로 합친다. 출처 우선순위를 둔다 |
| 날짜로 **상태(모집 중·마감)를 계산** | 그대로. 날짜로 못 읽은 기한("예산 소진 시")은 "마감 확인 필요" |
| 뉴스로만 본 항목은 **"미확인"**, 사이트에 "미확인 숨기기" | 신뢰 단계(5절)로 확장 |
| **사람이 단 정답 라벨로 정확도를 잰다** (`eval/`) | 대상·분야 판정의 정확도를 같은 방식으로 잰다 |
| 규칙 키워드를 **관리 화면에서 고치면** 다시 수집 | v1. 처음에는 `config/*.json`을 PR로 고친다 |

**가져오지 않는 것**: 민간 공모전 모음 사이트의 목록을 긁어 다시 보여 주는 방식. 우리는 공식 출처를 먼저 쓴다 (D17).

## 3. 흐름

```
매일 06:00 KST (GitHub Actions)
  crawler/sources/*      공식 API·CSV에서 받기 (수정일시로 새것·바뀐 것만)
  crawler/normalize.py   help 스키마 모양으로 바꾸기 (id, type, title, provider, url, 기한, 지역, 나이, 비용)
  crawler/youth.py       청소년 대상 걸러내기 (4절)
  crawler/attach.py      어느 분야·단계에 붙일지 (4절)
  crawler/merge.py       중복 합치기, 날짜로 상태 계산
  → data/collected/items.json, meta.json 커밋
  → 검사(validate) → 사이트 빌드
사람 (주 1회)
  검토 목록에서 확인 → data/processed/helps/로 옮기거나, 규칙을 고친다
```

## 4. 판정: 청소년 대상인가, 어느 단계에 붙나

**청소년 대상 (규칙)**
1. 대상연령이 있으면 **14~24세와 겹치는지**.
2. 중·고등학생·대학생 대상 코드가 있으면 통과.
3. 지원대상·선정기준 글에 "청소년", "학교 밖", "검정고시", "만 ○세 이하"가 있으면 통과.
4. 연령 정보가 비어 있으면 버리지 않고 **글 검색으로 보완**하고, 애매하면 AI 보조로 보낸다.

**어느 단계에 붙나 (규칙 먼저)**
- 키워드 → 단계: "조리기능사·응시료" → `korean-cook-license`, "검정고시" → `ged-high`, "직업훈련·국비" → `cooking-training-course`, "체험·프로그램" → 체험 단계 등. 규칙은 `config/attach-rules.json`.
- 분야를 모르면 분야 공통(`field_ids`)으로 둔다.

**AI 보조 (공모전 레이더의 Jev 방식)**
- 질문: "만 14~24세가 신청할 수 있나?"(확률), "학교 밖 청소년이 신청할 수 있나?"(확률), "어느 단계에 가깝나?"(선택 + 확신도).
- **규칙이 먼저**다. AI는 확신이 높을 때만 뒤집는다(예: 0.85 이상 구해 오기, 0.15 미만 빼기).
- 답은 제목·본문 해시로 캐시해 새 항목만 보낸다. 실행마다 비용·지연을 `data/collected/ai_runs.jsonl`에 남긴다.
- 사람이 단 정답 50~100개로 정확도를 잰다. 정답을 만드는 기준은 `eval/GUIDELINE.md`로 둔다.

## 5. 신뢰 단계와 화면

| 단계 | 뜻 | 화면 |
|---|---|---|
| **확인됨** | 사람이 원문을 보고 확인해 `data/processed/helps/`에 옮김 | 그대로 보여 준다 |
| **공식 자동** | 정부 공식 API·CSV에서 자동으로 받음 (사람 확인 전) | 결정 대기 (아래) |
| **후보** | 공식 페이지 1차 확인만 됨, 또는 뉴스·수기로 본 것 | 사이트에 안 올린다 (시안에서만 "확인 전") |

**결정 필요 (`auto-publish`)**: "공식 자동" 항목을 사람 확인 없이 보여 줄까?
- 보여 주면: 당근이 바로 많아진다. 출처가 정부 공식 데이터라 신뢰도가 높다. "공식 데이터 · ○월 ○일 수집 · 신청 전 원문 확인"을 붙인다.
- 안 보여 주면: 정확하지만 사람이 모두 확인해야 해 느리다.
- **추천**: 보여 준다. 단 ① 대상 판정이 규칙으로 확실한 것만, ② 마감을 날짜로 읽은 것만, ③ "공식 데이터에서 자동으로 모았어요" 표시와 수집일, ④ 신고 버튼(v1). 나머지는 검토 목록으로 간다.

## 6. 사람이 할 일

- **검토 목록** (주 1회, 30분 목표): 규칙과 AI가 애매하다고 한 항목, 공식 피드가 없는 곳(꿈드림, 교육청, 지자체, 대회).
- **키 발급**: data.go.kr 회원가입 후 활용신청 (보조금24, 청소년 활동, 자원봉사, 큐넷). 키는 GitHub Secrets에만 둔다.
- **걸린 시간 기록**: 수작업 항목 하나에 몇 분 걸렸는지 적는다(1주차 약속). 자동화 범위를 정하는 근거가 된다.

## 7. 조심할 점

- **중복**: 같은 사업이 보조금24, 온통청년, 장학재단에 동시에 있다. ID로 연결되지 않으니 이름·기관 정규화로 합친다.
- **마감이 지난 항목**: 기한이 자유 텍스트다. 날짜로 못 읽으면 "마감 확인 필요"와 수집 시각을 보여 준다.
- **연령 정보 없음**: 버리지 말고 글 검색·AI로 보완한다.
- **반기 갱신 데이터**(인증프로그램 CSV)는 모집 공고로 쓰지 않는다.
- **출처 표기**: data.go.kr 데이터는 이용허락범위 제한이 없지만 출처를 밝힌다. 민간 사이트 글은 복제하지 않는다.
- **트래픽 한도**: 개발계정 한도(큐넷 1천, 나머지 1만 건)는 매일 증분에 충분하다. 처음 전체를 받을 때만 나눠 받는다.
