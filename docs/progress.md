## 요약

- **0단계: 문제 검증 준비 중.** 코드는 아직 없다. 기획 문서(README, 경쟁 분석, 검증 계획, 로드맵)만 있다.
- **서비스 중심을 '진로 대화'로 옮겼다.** 사람(멘토)이 중심이고 AI는 보조, 혜택 정보는 실행 지원 도구다 (D6). README, 검증 계획, 로드맵을 새 방향에 맞게 고쳤다.
- **MVP는 멘토 연결이 아니라 콘텐츠 + 로드맵 도구 + 구독으로 사람 모으기** (D7). 한 줄 소개는 "지금 내 자리에서 시작하는 진로". 설계는 `docs/mvp.md`.
- 기획 로드맵, MVP 설계, 자금 조사, 현황판은 **PR #1로 `main`에 머지됐다** (374f001).
- 문제 정의를 **확인된 것과 가설로 나눴다.** "같이 고민해 줄 어른이 없다"는 근거가 없어서, H1을 "여러 길을 간 어른을 만날 기회가 적다"로 고치고 가설로 남겼다.
- MVP는 **커리큘럼이 아니라 '지도'**를 준다: 마일스톤, 단계별 지원과 **대회·활동**, 사람 이야기 (D8).
- **소셜벤처로 간다** (D9). 학생은 무료, 기관이 돈을 낸다. 개인 식별 데이터는 팔지 않고 합친 통계만 쓴다 (D10). 수익 모델은 `docs/business-model.md`.
- **선택 가입을 v0부터**, 만 14세 이상만, 최소 수집 (D11). 커뮤니티는 **고민 Q&A부터**, 또래 댓글은 사람이 모인 뒤 (D12). 가입은 **학생 트랙 만 14~24세**, 어른 트랙은 v1에 따로 (D13).
- 하고 싶은 게 없는 학생용 **관심 찾기 퀴즈 + 체험** (D14). 진단이 아니라 분야 3개와 체험을 보여 준다.
- 근거를 **2025 학교 밖 청소년 실태조사**로 갱신했다: 학업중단 후 어려움 1위가 진로 찾기(26.9%), 진로 계획 모름 42.4%, 적성 모름 41.2%. 1주차 미션 내용은 `docs/week1-problem-definition.md`.
- 1주차 미션 PPT 완성 (팀명 Team 유이정, 파일은 저장소 밖). 논문 2건 추가: 연구원(2025)은 **69.5%가 진로 계획을 세운 적이 있다**고 해, 문제 정의를 과장하지 않도록 주의.
- 로드맵마다 기록이 쌓이는 **나의 기록(포트폴리오)**을 v1부터 작게 (D15). e청소년이 인증 활동 기록·포트폴리오를 이미 제공해, 차별점은 인증 밖 활동·로드맵 연결·이력서 초안.
- 전체 그림: **탐색(퀴즈·스와이프·미션, D16) → 지원 추천을 계속 갱신하는 당근(D17) → 반자동 기록·포트폴리오 → 법 확인 뒤 취업 연계(D18) → 청소년에서 증명 뒤 20대 이상 확장(D19)**.
- 아키텍처 설계 문서(`docs/architecture.md`, Fable 작성·Opus 검토)가 PR #11로 `main`에 들어갔다. 검토 메모: 트랙을 `learner`/`supporter`로 나누기(D19), 스와이프·미션 저장 자리(D16), 선택형 `help_clicks`(D18).
- **행동 데이터는 최대로, 합친 통계로 B2G·B2B 활용** (D20). 사용자는 개인정보도 최대로 모으길 원해, **법률 검토 전까지는 D11(최소 수집) 유지**로 결정 대기에 올렸다.
- **1주차 개발 시작**: 데이터 형식(JSON Schema), 요리사 분야 초안(길 4개, 단계 8개, 도움은 비어 있음), 자동 검사(`npm run validate`), Astro 사이트 뼈대(`/fields/cooking`), 전체 검사 `python tests/verify.py`, PR 자동 검사.
- **데이터 전략**(`docs/data-strategy.md`): 팔리는 것은 데이터 자체보다 조사·성과측정 용역과 도달 채널. 상품 4개(조사 용역, 성과 측정 리포트, 도달+전환 리포트, 무료 트렌드 리포트), 이벤트 11개, 설문, 동의 4단계, 소수 칸 숨김 k=10 제안.
- **요리사 완성본**: 디자인 다듬기, 글 초안 "요리사가 되는 여러 길"(초안, 출처 4개), 도움 후보 9개(`data/candidates/`, 사이트에 안 올림), Fable 검토 반영. 강의용 기록 `docs/course-log.md` 시작.
- **디자인 방향 결정 (D22)**: 시안 3개(노선도, 다꾸, 대화형)를 만든 뒤 **대화로 시작 → 지하철 노선도 → 혜택 자동 표시**로 정했다. 합친 시안(`/concepts/combo`)이 나왔다: 답에 맞게 혜택이 걸러져 노선도 옆에 뜬다. 혜택은 확인 전 후보라 '확인 전' 표시.
- **시안 4를 본 사이트에 적용**: 요리사 페이지(대화 → 노선도 → 혜택), 홈, 읽을거리, 글, 404가 같은 디자인 언어(`Site.astro`, `tokens.css`). 본 페이지 혜택은 확인된 데이터만이라 지금은 "확인하는 대로 떠요". 후보 5개 1차 확인 보고서 `data/candidates/cooking-helps-check.md`.
- **혜택 수집 설계** (`docs/collection-strategy.md`): data.go.kr 공식 API(보조금24, 장학재단, 청소년 활동·자원봉사, 큐넷) + 공모전 레이더의 파이프라인. 첫 단계는 data.go.kr 키 발급(사용자).
- **혜택 수집기 1단계** (`crawler/`): 공식 출처 5개(큐넷 시험일정, 장학재단 장학금, 청소년활동 인증·신고, 자원봉사)를 모으고, 규칙으로 14~24세 여부와 단계를 정한 뒤 **Jev가 두 번째 의견**을 준다(공모전 레이더 방식). 첫 실행: 1,043개 중 단계에 붙은 31개(큐넷 27, 학교 밖·검정고시 장학금 4), 검토 목록 887개, Jev 비용 약 $0.045. 결과는 `data/collected/`에만 있고 사이트는 아직 안 읽는다.
- **사이트 공개**: https://sweet-butters.github.io/youth-benefit-finder/ (GitHub Pages, main에 머지하면 자동 배포, 수집기 실행 뒤에도 배포). 요리사 페이지에 **'공식 자동' 혜택**이 뜬다(D23): 한식조리기능사 원서접수(회차 묶음, D-n), 광주 서구 학교밖청소년 장학금. 지역 질문은 17개 시·도로(D24).
- 다음 큰 일정은 2026년 10월 꿈드림 AI 교육 봉사 시작과 당사자 인터뷰다.
- 자금: 맞는 공모·지원사업은 대부분 봄에 열린다. 가을은 근거를 쌓고, **2027년 3~4월 사회적기업가 육성사업**을 주 목표로 지원한다 (`docs/funding.md`).
