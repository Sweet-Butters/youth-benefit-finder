# 데이터 전략: B2G·B2B 수요에 맞춘 설계

> 작성일: 2026-09-26. 결정 D20(행동 데이터는 최대로, 합친 통계로만 활용), D10(개인 식별 데이터 판매 금지), D11(신원 정보 최소)을 따른다.
> 저장 구조는 `docs/architecture.md`(2~3절)를 확장한다. 수요 조사는 웹 조사 결과이고, 각 항목에 **확인됨 / 추측 / 확인 못함**을 적었다.
> 개인정보 확대(`pi-expansion`)는 법률 검토 전이라 이 문서에 넣지 않았다.

## 0. 한 줄 요약

정부와 기업이 돈을 내는 것은 **"데이터 자체"보다 조사·성과측정 용역과 청소년에게 닿는 채널**이다. 그래서 우리가 쌓는 데이터는 ① 센터 밖 청소년까지 닿는 **표본**, ② 사전·사후 **변화 측정**, ③ 추천 → 클릭 → 신청의 **전환 기록**을 만드는 데 맞춘다. 트렌드 리포트는 무료로 풀어 신뢰를 쌓는다.

## 1. 수요 조사 요약

### B2G: 정부가 보는 지표와 공백

| 누가 | 무엇을 보나 | 신뢰도 |
|---|---|---|
| 성평등가족부·꿈드림 | 지원 인원(2023년 38,329명, 2024년 39,930명), 사회진입 성과(검정고시 합격, 취·창업, 자립역량 향상) | 확인됨 ([한경](https://www.hankyung.com/article/2025112535631)) |
| 학교 밖 청소년 실태조사 (3년 주기) | 학업중단 이유, 건강, 가족, 경제, 진로, 지원 이용·수요 | 확인됨 ([공공데이터포털](https://www.data.go.kr/data/15123387/fileData.do)) |
| 교육부·한국직업능력연구원 진로교육 현황조사 (매년) | 희망직업, 진로활동 만족도, 진로교육 요구 | 확인됨 ([KRIVET](https://www.krivet.re.kr/kor/sub.do?menuSn=12&pstNo=PB0000000722)) |
| 제7차 청소년정책 기본계획 (2023~2027) | 진로 지원, 학교 밖 청소년 자립 과제 포함. 목표값은 원문 확인 못함 | 구조만 확인됨 |

**공백 (우리가 채울 수 있는 곳)**
- **센터 밖 청소년**: 학교 밖 청소년 약 17.4만 명 중 꿈드림 지원 인원은 약 3.9만 명이다. 절반 이상이 센터 밖에 있을 가능성이 크다 (두 수치로 계산한 **추측**).
- **정보 연계**: 학업중단 당시 정보를 센터가 받은 비율은 48.3%였다 (확인됨, [KEDI](https://edpolicy.kedi.re.kr/edpolicy/webzine/39/842348)). 2024년 9월 법 개정으로 동의 없이도 넘길 수 있게 됐다.
- **사후 추적**: 공식 자료에서 명시한 것을 찾지 못했다 (확인 못함).

### 공공 조달

- 청소년 실태조사는 외부 용역이 일반적이다. 한국청소년정책연구원 조사 입찰 약 4.1억 원, 서울시 학교 밖 청소년 실태조사 배정 1억 원(이후 취소 공고) (확인됨).
- 데이터바우처(2025): 과제당 최대 4,500만 원. 공급기업 등록 경로는 있으나 청소년 진로 데이터 사례는 없다 (확인됨·사례는 확인 못함).
- 공공이 민간의 청소년 **행동 데이터를 산** 사례는 찾지 못했다 (확인 못함).
- **해석 (추측)**: 팔리는 것은 조사를 대신 수행하는 **용역**이다. 센터 밖 청소년 표본이 경쟁력이 된다.

### B2B·CSR

| 방식 | 측정 | 신뢰도 |
|---|---|---|
| SK 사회성과인센티브(SPC) | 성과를 화폐로 환산. 대략 **수혜자 수 × 개선 효과 × 단가**. 청소년 교육 단체 '점프'가 참여 | 확인됨 ([CSES](https://www.cses.re.kr/business/measurement.do)) |
| SROI | 사회적 편익 ÷ 투자액 | 확인됨 |
| IRIS+ | 표준 지표. 예: 취업 연계 수(PI9465) | 확인됨 ([IRIS+](https://iris.thegiin.org/metric/5.3/pi9465/)) |

- 기업이 파트너에게 참여자 수, 사전·사후 변화, 사후 성과를 요구한다는 것은 **추측**이다. 임팩트 리포트의 실제 양식은 찾지 못했다.

### 홍보·모집

- 링커리어·씽굿 같은 공모전 플랫폼은 **공고 등록은 무료, 배너·뉴스레터 노출은 유료**다. 단가는 비공개 (확인됨).
- **해석 (추측)**: 일반적인 모델은 노출 판매다. 우리는 여기에 **클릭 → 신청 전환 리포트**를 붙여 차별화한다.

### 비슷한 데이터 상품

| 서비스 | 측정 | 수익 | 신뢰도 |
|---|---|---|---|
| 대학내일20대연구소 | 세대 트렌드, 소비 | 컨설팅, 데이터 판매, 멤버십 | 확인됨 |
| 오픈서베이 | Z·알파세대 (만 14~29세) | 리포트는 무료, 조사 플랫폼 판매로 연결 | 확인됨 |
| Handshake | 학생 지원·채용 트렌드 | 리포트 무료, 기업 채용 구독 (추측) | 리포트 확인됨 |
| Common App | 지원자 인구통계 | 무료 연구 브리프 | 확인됨 |

**해석 (추측)**: 합친 리포트는 대개 **무료로 풀어 신뢰를 쌓는 도구**이고, 돈은 컨설팅·구독·홍보에서 난다.

## 2. 우리가 팔 것

| 상품 | 누가 사나 | 담는 지표 | 필요한 데이터 | 시기 |
|---|---|---|---|---|
| **A. 조사 용역** | 지자체, 교육청, 연구기관 | 센터 밖 청소년의 관심·막힘·필요 | 선택 설문, 나이대, 시·도, 행동 요약 | 2~3년 차 (표본이 쌓인 뒤) |
| **B. 성과 측정 리포트** | 기업 CSR, 재단, 지원사업 성과 보고 | 참여자 수, **사전·사후 변화**, 해낸 단계, 신청 수. SPC(인원 × 변화)·IRIS+ 형식에 맞춘다 | 사전·사후 설문, `step_done`, `help_applied` | 1~2년 차 (지원사업 성과 보고부터) |
| **C. 도달 + 전환 리포트** | 대회 주최, 훈련기관, 청소년 기관 | 노출, 클릭, "신청했어요" 전환 | `help_viewed`, `help_clicked`, `help_applied` | 구독자가 모인 뒤 |
| **D. 무료 트렌드 리포트** | 누구나 (신뢰·유입용) | 지역·나이대별 관심 분야, 많이 저장한 길 | 퀴즈·스와이프·저장 | 첫 3개월 점검 뒤부터 분기마다 |

**가장 먼저 쓸 곳은 B다.** 2027년 봄 지원사업(사회적기업가 육성사업)에 지원할 때 "몇 명이 무엇을 해냈고, 무엇이 달라졌나"를 보여 주는 데 바로 쓴다.

## 3. 쌓을 이벤트

두 층으로 나눈다.
- **익명 방문 통계**: 누구나. 쿠키 없는 도구. 개인과 연결하지 않는다.
- **가입자 행동 기록**: 가입하고 **행동 기록에 동의한 학생만**. Supabase `events` 표에 쌓는다 (6절).

| 이벤트 | 언제 | 모으는 값 | 모으지 않는 값 | 층 | 쓰는 상품 |
|---|---|---|---|---|---|
| `page_viewed` | 페이지를 볼 때 | 경로, 유입 경로, 기기 종류 | IP 저장, 쿠키, 지문 | 익명 | D |
| `quiz_completed` | 퀴즈를 끝냈을 때 | 분야 3개, 홀랜드 점수 6개 | 문항별 답 원문 | 익명 + 행동 | A, D |
| `swipe` | 카드를 넘길 때 (D16) | 카드 ID, `like`/`skip` | — | 행동 (비가입은 브라우저에만) | D |
| `roadmap_viewed` | 길 페이지를 볼 때 | 분야 ID, 길 ID | — | 익명 + 행동 | A, D |
| `roadmap_saved` | 결과를 저장할 때 | 분야 ID, 길 ID | — | 행동 | D |
| `help_viewed` | 도움 항목이 화면에 보일 때 | 도움 ID | — | 익명 | C |
| `help_clicked` | 도움 링크를 누를 때 | 도움 ID | — | 익명 + 행동 | C |
| `help_applied` | 며칠 뒤 "신청했어요?"에 답할 때 (D18) | 도움 ID, `yes`/`no`/`later` | 신청 내용 | 행동 | B, C |
| `step_done` | "해냈어요"를 누를 때 (D15) | 단계 ID, 날짜 | 한 줄 후기 원문 (통계에 쓰지 않음) | 행동 | B |
| `mission_done` | 미션을 해냈을 때 (D16) | 미션 ID | 사진 | 행동 | B |
| `survey_answered` | 설문에 답할 때 (4절) | 설문 ID, 문항별 보기 코드 | 자유 입력 | 행동 | A, B |

- **이탈 지점**은 따로 이벤트를 두지 않는다. 위 이벤트의 순서(퀴즈 → 조회 → 저장 → 클릭 → 신청 → 해냄)로 계산한다.
- 모든 값은 **보기 코드나 ID**만 쓴다. 자유 입력 문장은 통계에 넣지 않는다.
- 로그인 뒤 페이지(`/me/*`)에는 익명 통계 스크립트를 넣지 않는다 (architecture.md 3절).

## 4. 설문

짧게, 선택으로, 목적을 밝히고 받는다.

| 설문 | 언제 | 문항 (예시, 문구는 팀이 다듬는다) | 쓰는 상품 |
|---|---|---|---|
| **시작 설문** | 가입 직후 (건너뛸 수 있음) | 진로를 정했나요 (4단계) / 지금 가장 필요한 도움 (보기 선택) / 이번 달에 해 보고 싶은 것 | A, B (사전) |
| **30일 후 설문** | 가입 30일 뒤 알림 | 같은 문항 + 지난 한 달 해 본 것 | B (사후) |
| **90일 후 설문** | 가입 90일 뒤 | 같은 문항 | B (사후) |
| **상황 설문** | 선택, 언제든 | 지금 학교에 다니나요 등 | A |

- **사전·사후 같은 문항**이어야 변화를 잴 수 있다. 이것이 SPC식 "인원 × 변화" 계산의 바탕이다.
- 검증된 척도(자기효능감 등)를 쓰려면 사용 허락과 원문을 확인해야 한다. 그전까지는 우리가 만든 짧은 문항을 쓰고, 리포트에 그렇게 밝힌다.
- 학교 재학 여부처럼 민감할 수 있는 문항은 **법률 확인 뒤** 넣는다.

## 5. 동의 화면

가입 때 네 가지를 **따로** 보여 준다. 선택 항목은 미리 체크해 두지 않는다.

| 동의 | 필수/선택 | 목적 (화면 문구 예시) | 안 하면 |
|---|---|---|---|
| ① 가입 정보 | 필수 | "로그인과 내 로드맵 저장에 써요" | 가입 불가 |
| ② 행동 기록 | 선택 | "어떤 길을 보고 무엇을 해냈는지 기록해 '나의 기록'과 청소년 지원 개선 통계에 써요. 통계에는 개인을 알 수 없는 숫자만 나가요" | 기록·추천 일부가 빠질 뿐, 서비스는 다 쓴다 |
| ③ 설문 | 선택 | "진로가 어떻게 달라지는지 보고 청소년 지원을 개선하는 데 써요" | 설문만 안 뜬다 |
| ④ 알림 | 선택 | "관심 분야의 새 지원·대회와 '신청했어요?' 확인을 보내요" | 알림만 안 온다 |

- 설정 페이지에서 **언제든 끄고 켤 수 있다.** 끄면 그 뒤로 쌓지 않는다. 이미 쌓인 기록을 지울지는 학생이 고른다.
- 동의 문구와 버전을 `consents` 표에 남긴다 (6절). 문구가 바뀌면 다시 묻는다.
- 가명정보를 통계에 쓰는 것(개인정보보호법 제28조의2)은 동의 없이도 가능하다는 해석이 있지만, 우리는 **②의 동의를 받은 기록만** 쓴다. 처리방침에는 가명처리와 통계 활용을 적는다.

## 6. 저장 구조 (architecture.md 확장)

architecture.md 2절의 표에 아래를 더한다. 모두 RLS로 **본인 행만** 읽는다.

| 표 | 열 | 메모 |
|---|---|---|
| `consents` | `user_id`, `kind` (`behavior`/`survey`/`notify`), `version`, `granted_at`, `revoked_at` | 동의 이력. 현재 동의는 `revoked_at IS NULL`인 최신 행 |
| `events` | `id`, `user_id`, `name` (3절 목록만, CHECK), `props jsonb` (ID·코드만), `created_at` | `behavior` 동의가 있을 때만 쓴다 (DB 함수에서 확인) |
| `survey_responses` | `id`, `user_id`, `survey_id`, `answers jsonb` (보기 코드만), `created_at` | `survey` 동의가 있을 때만 |
| `preferences` | architecture.md 검토 메모 2 (스와이프) | `events`의 `swipe`와 겹치면 하나로 합친다 (구현 때 정함) |
| `help_clicks` | architecture.md 검토 메모 3 | `events`의 `help_clicked`로 대신할 수 있다 (구현 때 정함) |

**통계 만들기**
- 매주 GitHub Actions가 서비스 롤로 집계해 `stats_weekly`에 **개수만** 쓴다 (architecture.md 3절).
- **소수 칸 숨김 기준 k**: 조사에서 공식 기준을 찾지 못했다. 내부 기준으로 **k = 10**을 제안한다(k 미만 칸은 쓰지 않는다). 전문가 확인 뒤 확정한다.
- 한 통계에서 쪼개는 기준은 **최대 두 가지**(예: 지역 × 분야)로 둔다. 셋 이상 쪼개면 초기에는 한 명이 드러난다.
- 개인 행을 Supabase 밖으로 내보내는 작업은 없다. 리포트는 `stats_weekly`만 읽어 만든다.

**보관 기간 (가정, 처리방침 확인 필요)**
- `events` 원본: 1년 보관 뒤 집계만 남기고 지운다.
- 탈퇴: 모든 표에서 즉시 삭제 (architecture.md 3절). 이미 만든 주간 개수는 개인 행이 아니라 남는다.

## 7. 지표 정의

리포트와 대시보드가 같은 뜻으로 쓰도록 정해 둔다.

| 지표 | 정의 |
|---|---|
| 도달 | 기간 중 방문자 수 (익명 통계) |
| 탐색 완료율 | 퀴즈를 끝낸 방문 ÷ 퀴즈를 시작한 방문 |
| 저장률 | 로드맵을 저장한 가입자 ÷ 로드맵을 본 가입자 |
| 신청 전환율 | `help_applied = yes` ÷ `help_clicked` (같은 도움, 가입자 기준) |
| 행동한 학생 | 기간 중 `step_done` 또는 `mission_done`이 1개 이상인 가입자 수 (H2 지표) |
| 진로 결정 변화 | 사전 대비 30·90일 후 "진로를 정했다" 쪽으로 옮긴 비율 |
| 재방문율 | 가입 30일 뒤에도 방문한 가입자 비율 |

## 8. 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 개인 단위 데이터 판매·제공 | D10. B2G 협력처가 떠난다 |
| 개인 맞춤 광고, 광고 타게팅 | D2, D10 |
| 세션 녹화, 브라우저 지문, 추적 쿠키 | 미성년자. 필요한 최소 범위를 넘는다 |
| 민감정보(건강, 장애 등) 수집 | 법률 검토 전에는 없음 |
| 자유 입력 문장의 통계 활용 | 개인이 드러날 수 있다 |
| 개인정보 항목 확대 | `pi-expansion`. 법률 검토 뒤 결정 |

## 9. 열린 질문과 법률 확인

1. 소수 칸 숨김 기준 k (제안 10)와 쪼개는 기준 최대 개수(제안 2)
2. `events` 원본 보관 기간 (제안 1년)
3. 선택 동의 화면 문구와 처리방침의 가명정보·통계 활용 기재 (전문가 확인)
4. 사전·사후 설문 문항: 검증된 척도를 쓸지, 우리 문항을 쓸지
5. 상황 설문의 재학 여부 문항을 넣을지 (법률 확인)
6. 성과 측정 리포트(B)의 첫 형식: 사회적기업가 육성사업 성과 보고 양식에 맞춘다 (공고가 나오면 확인)
7. 공공기관에 통계를 낼 때의 요건 (전문가 확인)
