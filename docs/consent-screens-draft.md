# 동의 화면 문구 초안 (가입·마감 알림·AI 고민 읽기·탈퇴)

> 2026-09-27 작성. **초안이다. 법률 자문이 아니다.** 처리방침 초안 `docs/privacy-policy-draft.md`와 짝이다. 두 문서의 항목·기간·업체가 **한 글자도 다르지 않아야** 한다. 동의받을 때 알린 내용과 처리방침이 다르면 잘못 작성된 사례가 된다(작성지침 21·34쪽).
> 대상은 만 14~24세다. 문장은 **중학교 2학년이 한 번 읽고 알 수 있게** 쓴다. 한 문장에 한 가지만 말하고, 법률 용어는 괄호로만 붙인다.
> 표시: **[사실]** 법·공식 지침 / **[해석]** 우리 판단 / **[가정]** 우리가 고른 기본값 / **[확인 필요]** 전문가·업체 확인이 필요한 것 / `<...>` 채울 빈칸

| 개인정보를 주는 대가로 현금·아이템을 주지 않는다 | 아동·청소년 안내서 1-3 (25쪽) | "가입하면 선물" 같은 문구를 쓰지 않는다 |

**2023년 개정으로 달라진 것 (한 문단 요약)**
**[사실]** 2023.3.14. 개정법(2023.9.15. 시행)은 정보통신서비스 제공자의 '필수 동의' 특례(옛 제39조의3)를 없앴다. 이제 서비스 계약을 이행하는 데 필요한 정보는 동의 없이 처리할 수 있다(제15조제1항제4호). 계약과 관계없는 정보만 동의를 받는데, 그 동의는 정말로 고를 수 있어야 한다. 시행령 제17조제1항의 동의 요건 네 가지는 2024.9.15.부터 적용된다(통합 안내서 20쪽, 129~130쪽).
**[해석]** 그래서 작업 지시의 "필수 동의"는 화면에서 **'가입에 꼭 필요한 정보: 안내 + 확인'**으로 바꿨다. 필수와 선택을 나눈다는 뜻은 그대로다. **[확인 필요]** 처리방침 초안 2-1의 질문(미성년자 계약에 제4호를 써도 되는지)이 "안 된다"로 나오면 1-2의 안내를 **따로 된 필수 동의 체크 상자**(꺼진 채 시작)로 바꾼다.

## 1. 가입 (M3)

가입은 **저장하고 싶을 때만** 한다(D11 "먼저 써 보고 저장하려면 가입"). 버튼 문구는 "가입하기"가 아니라 **"저장하려면 가입하기"**다.

### 1-1. 나이 확인 (첫 화면)

```
몇 살이에요? (만 나이)

( ) 만 14~16세
( ) 만 17~19세
( ) 만 20~24세
( ) 만 14세가 아직 안 됐어요
( ) 만 25세 이상이에요

만 나이 계산: 올해 생일이 지났으면 (올해 − 태어난 해),
안 지났으면 거기서 1을 더 빼요.

[다음]
```

- 아무것도 미리 골라 두지 않는다. '만 14~16세'가 맨 위라고 기본 선택하지 않는다.
- 이 답이 곧 **나이대**(D11)다. 생년월일은 받지 않는다.
- **[사실]** 연령 확인은 생년월일 입력 또는 "만 14세 이상" 자기 체크로 할 수 있다(아동·청소년 안내서 22~23쪽). 우리 방식은 자기 체크의 한 형태다(해석).

**"만 14세가 아직 안 됐어요"를 고르면**

```
가입은 만 14세부터 할 수 있어요.
법에서 만 14세가 안 된 사람의 정보는 보호자 허락이 있어야
받을 수 있게 정했거든요.

가입하지 않아도 노선도, 혜택 게시판, 찾기 대화는 다 쓸 수 있어요.
고른 답은 이 기기에만 남아요.

[가입 없이 계속 보기]
```

- 이 선택은 **저장하지 않는다.**
- **[가정]** 부정 가입 방지(아동·청소년 안내서 1-5): 이 화면을 본 뒤 같은 탭에서 곧바로 나이를 바꾸면 "나이를 바꿨네요. 정말 만 14세 이상인가요?"를 한 번 더 묻는다. 세션 안에서만 기억하고 IP는 쓰지 않는다. **[확인 필요]** 이 정도로 '합리적인 장치'가 되는지.

**"만 25세 이상이에요"를 고르면**: "지금은 만 24세까지 학생 트랙만 있어요(D13). 부모님·선생님·멘토 트랙은 준비 중이에요."

### 1-2. 가입에 꼭 필요한 정보 (안내 + 확인)

```
가입하려면 이 정보가 꼭 필요해요

무엇을        왜                         언제까지
로그인 정보   로그인할 때 여러분인지 확인   탈퇴하면 바로 지워요
 (이메일 또는
  카카오 회원번호)
닉네임        화면에 부를 이름             〃
나이대        만 14세 이상 확인,           〃
              나이에 맞는 혜택 보여 주기
저장한 것     결과·노선도·혜택 다시 보기    〃

어디에 두나요: Supabase라는 회사의 서버(서울)에 둬요. <운영사 해외 접근 여부 [확인 필요]>
누구에게 주나요: 아무에게도 주지 않아요. 팔지도, 광고에 쓰지도 않아요.
이름, 전화번호, 학교, 생년월일은 묻지 않아요.

자세한 건 [개인정보 처리방침]에 있어요.

[확인했어요, 다음]   [가입 안 할래요]
```

- **[해석]** 이 화면은 동의가 아니라 **고지**다. 그래서 체크 상자가 없고 버튼이 '확인'이다(통합 안내서 129쪽 '고지 후 확인').
- 백업 보관(N일)은 "탈퇴하면 바로 지워요" 아래 작은 글씨가 아니라 탈퇴 화면(4절)에 같은 크기로 적는다.
- 이용약관이 생기면 개인정보 안내와 **다른 화면**으로 둔다. 한 상자로 묶지 않는다.

### 1-3. 고르는 것 (선택, 모두 꺼진 채 시작)

```
원하는 것만 켜 주세요 (선택)
아무것도 안 켜도 가입하고 다 쓸 수 있어요.

[ ] 사는 곳과 관심 분야 기억하기 (선택)
    무엇을: 사는 시·도, 관심 분야
    왜: 혜택을 볼 때마다 다시 고르지 않게
    언제까지: 끄거나 탈퇴할 때까지
    안 켜면: 혜택을 볼 때 그때그때 고르면 돼요

[ ] 마감 알림 받기 (선택)
    무엇을: 로그인 이메일, 알림을 켠 혜택
    왜: 저장한 혜택 마감 3일 전에 이메일로 알려 주려고
    언제까지: 알림을 끄거나 탈퇴할 때까지 (보낸 기록은 30일)
    안 켜면: 알림만 안 와요
    누가 보내나요: <메일 발송 회사> (<나라>)

[ ] 나의 기록 쌓기 (선택)
    무엇을: 본 노선도·혜택, 누른 원문 링크, '신청했어요'·'해냈어요'
            (무엇을 언제 했는지만. 글 내용은 안 받아요)
    왜: '나의 기록'을 보여 주고, 개인을 알 수 없는 숫자
        (예: "서울에서 요리 노선을 저장한 사람 12명")로
        청소년 지원을 좋게 만드는 데 쓰려고
    언제까지: 1년 뒤 원본은 지우고 합계만 남겨요. 끄면 그 뒤로는 안 쌓아요
    안 켜면: '나의 기록'이 비어 있을 뿐, 다른 기능은 다 써요

[가입 마치기]
```

- **'모두 동의' 버튼을 만들지 않는다.** **[해석]** 법이 '모두 동의'를 금지하지는 않는다. 하지만 청소년 대상 화면에서는 한 번에 다 켜게 이끄는 장치가 되기 쉽다. 항목이 세 개뿐이라 없어도 불편하지 않다.
- [가입 마치기]는 아무것도 켜지 않아도 눌린다.
- 켠 항목마다 `consents` 표에 `kind`, `version`, `granted_at`을 남긴다(`docs/data-strategy.md` 6절).
- **[확인 필요]** 마감 알림을 동의가 아닌 '신청'(계약)으로 볼지. 어느 쪽이든 화면은 이대로 쓴다.

### 1-4. 가입 끝

```
가입했어요, <닉네임>님!
켠 것: 마감 알림 · 끈 것: 사는 곳 기억하기, 나의 기록
언제든 [내 설정]에서 바꿀 수 있어요.
```

- 무엇을 켰고 무엇을 껐는지 **한 번 더 보여 준다.** 모르고 켠 것이 없게 한다.

## 2. 마감 알림 켜기 (가입 뒤, 혜택 상세 화면에서)

```
이 혜택 마감 3일 전에 알려 드릴까요?

- 알림은 로그인 이메일(<a***@example.com>)로 가요.
- 알림에는 혜택 이름, 마감일, 원문 링크만 있어요. 광고는 없어요.
- 메일은 <메일 발송 회사>(<나라>)가 대신 보내요.
- 메일 맨 아래 [알림 끄기]를 누르면 바로 멈춰요.

[알려 주세요]   [괜찮아요]
```

- 처음 켤 때만 이 설명을 보여 준다. 그 뒤에는 혜택마다 종 모양 버튼(켜기·끄기)만 둔다.
- 1-3에서 '마감 알림'을 켜지 않은 사람이 여기서 [알려 주세요]를 누르면, 이것이 곧 동의다. `consents`에 기록한다.
- **[가정]** 보내는 시간: 오전 9시~오후 8시. **[사실]** 영리목적 광고성 정보는 오후 9시~다음 날 오전 8시에 보내려면 별도 동의가 필요하다(정보통신망법 제50조제3항). **[해석]** 우리 알림은 광고가 아니라 적용받지 않을 것이다. 그래도 청소년이라 밤에는 보내지 않는다. **[확인 필요]** 광고성 해당 여부.
- **[가정]** 카카오 알림은 나중에 연다. 전화번호가 필요해 D11에 없는 항목이 늘어난다(`pi-expansion`).

## 3. AI 고민 읽기 (M3)

D27: 고민 글은 처리방침과 이 동의 화면을 공개하기 전까지 **브라우저 밖으로 보내지 않는다.** M1·M2의 고민 한 줄 칸은 지금처럼 "저장·전송 없음"이다.

### 3-1. 보내기 전 안내 (처음 한 번 + 안내 내용이 바뀔 때)

```
AI가 내 고민을 읽고 생각해 볼 질문을 골라 줘요

어떻게 되나요
1. [보내기]를 누르면 방금 적은 글만 <AI 회사>(<나라>)로 가요.
   닉네임, 계정, 나이는 같이 보내지 않아요.
2. AI가 글을 읽고 생각해 볼 질문 3개를 골라요.
   진로를 정해 주거나 진단하지 않아요.
3. 우리는 글을 저장하지 않아요.
   <AI 회사>는 나쁜 사용을 막으려고 최대 <N>일 보관한 뒤 지워요.
   AI 학습에는 쓰지 않아요.            ← [확인 필요] 업체 약관과 똑같이

이런 건 적지 마세요
이름, 전화번호, 학교 이름, 주소, 다른 사람의 이야기.
건강이나 가족의 자세한 사정도 꼭 필요할 때만 적어 주세요.

[ ] 만 14세 이상이에요
[ ] 적은 글을 <AI 회사>(<나라>)에 보내는 데 동의해요 (선택)

[보내기]      [AI 없이 질문 보기]

지금 많이 힘들다면 AI 대신 바로 전화하세요.
청소년상담 1388 · 자살예방상담 109
```

- 두 상자는 **모두 꺼진 채** 시작한다. 둘 다 켜야 [보내기]가 눌린다. [AI 없이 질문 보기]는 언제나 눌린다.
- '만 14세 이상이에요'를 끈 채로 보내려 하면: "만 14세가 안 됐다면 AI 대신 질문 목록을 보여 드릴게요. 글은 보내지 않아요."
- 가입한 사람은 가입 때 확인한 나이대로 대신하고, 첫 번째 상자를 보여 주지 않는다.
- **[사실]** 생성형 AI 부록은 입력을 모으는지, 학습에 쓰는지, 보유 기간, 학습 거부 방법, 민감정보 입력 주의, 부적절한 답변 신고 방법을 알리라고 권한다(작성지침 2026.4. 부록 1, 120~127쪽). 국외 이전을 동의로 할 때는 이전되는 항목, 나라·시기·방법, 받는 자, 이용 목적·보유 기간, 거부 방법과 결과를 **미리** 알려야 한다(법 제28조의8제2항).
- **[해석]** 위 화면의 1~3번과 [AI 없이 질문 보기]가 법 제28조의8제2항의 다섯 가지를 모두 담는다. 받는 자의 연락처는 화면에 다 적기 어려워 처리방침 8절 링크로 둔다. **[확인 필요]** 링크로 둬도 되는지.
- **[해석]** 국내 AI를 고르면 "(<나라>)"와 국외 이전 설명이 빠지고 화면이 짧아진다.
- **[확인 필요]** 민감정보가 섞일 때 제23조 별도 동의가 필요한지(처리방침 초안 2-2). 필요하다고 나오면 세 번째 상자를 더한다: "[ ] 글에 건강·마음 상태가 들어 있을 수 있다는 걸 알고 보내요 (선택)".
- **[확인 필요]** "적은 글은 저장하지 않아요…"는 **우리와 AI 회사 모두** 보관하지 않을 때만 쓸 수 있다. AI 회사가 N일 보관하면 반드시 3번처럼 둘을 나눠 적는다.

### 3-2. 결과 화면 아래

```
이 질문은 AI가 골랐어요. 정답이 아니라 생각의 시작점이에요.
[이 답 신고하기]  (이상하거나 불편한 답이면 알려 주세요. 답만 받고 글은 받지 않아요)
```

### 3-3. 위기 표현이 있을 때

글에 스스로를 해치겠다는 표현이 보이면 AI 결과보다 먼저 다음을 보여 준다(D12의 1388 안내와 같은 원칙).

```
지금 많이 힘든 것 같아요. 혼자 견디지 않아도 돼요.
청소년상담 1388 (전화·문자·카카오톡) · 자살예방상담 109 · 긴급할 땐 112·119
```

- **[가정]** 위기 표현은 **브라우저 안에서** 단어 목록으로 먼저 거른다. 걸리면 AI로 보내기 전에 이 화면을 띄운다.

## 4. 탈퇴 (계정 삭제)

[내 설정] 첫 화면 맨 아래, 다른 버튼과 같은 크기의 **[탈퇴하기]**.

### 4-1. 확인 화면

```
탈퇴하면 이렇게 돼요

바로 지워지는 것
- 로그인 정보, 닉네임, 나이대
- 저장한 결과, 노선도, 관심 혜택
- 사는 곳·관심 분야, 마감 알림, 나의 기록, 올린 사진
- 동의 기록

남는 것
- 개인을 알 수 없는 합계 숫자 (예: "지난주 요리 노선 저장 12명")
  여러분이 누군지 알 수 없어서 지울 수 없어요.
- 서버 백업에 남은 사본은 최대 <N>일 뒤 자동으로 지워져요.  ← [확인 필요]

(v1) 지우기 전에 [내 기록 내려받기]

[탈퇴하기]   [취소]
```

- 버튼은 두 개다. 색·크기는 같게 하고, 취소를 더 크게 하거나 탈퇴를 회색으로 숨기지 않는다.
- 비밀번호나 이유 입력을 요구하지 않는다(가입 때 받지 않은 것을 탈퇴 때 요구하면 가입보다 어려워진다. 법 제38조제4항). **[가정]** 이유 묻기는 선택 한 줄로, 건너뛸 수 있게 한다.
- 탈퇴는 한 번의 요청으로 끝난다(`docs/architecture.md` 3절: Storage 파일 삭제 → `rpc('delete_my_account')`).

### 4-2. 끝

```
다 지웠어요. 그동안 고마웠어요.
가입하지 않아도 노선도와 혜택은 계속 볼 수 있어요.
```

- 탈퇴 확인 메일은 보내지 않는다 **[가정]**. 보내려면 지우기 전에 보내고, 메일 회사의 발송 기록 보관 기간을 처리방침에 적는다.

## 5. 내 설정: 켜고 끄기

```
내가 켠 것
사는 곳과 관심 분야 기억하기   [켜짐 ●]
마감 알림                      [꺼짐 ○]
나의 기록 쌓기                 [켜짐 ●]

끄면 그 뒤로는 모으지 않아요.
'나의 기록'을 끌 때: [지금까지 기록도 지우기] [기록은 남겨 두기]
```

- 켜기와 끄기는 같은 곳에서, 같은 한 번의 누름으로 한다.
- 동의 문구 버전이 바뀌면 다음 로그인 때 바뀐 부분만 보여 주고 다시 묻는다. 대답하기 전에는 **꺼진 것으로** 본다.

## 7. 개발 메모 (화면과 기록을 맞추려고)

- 모든 동의·확인 문구에 **버전**을 붙인다(`consent-v1-2026-XX`). `consents` 표에는 `kind`, `version`, `granted_at`, `revoked_at`을 쓴다.
- AI 동의는 `kind = 'ai_worry'`. 보낼 때마다 켜는 것이 아니라 처음 한 번 켜고, 문구 버전이 바뀌면 다시 묻는다. **[확인 필요]** 한 번의 동의로 이후의 전송을 모두 덮어도 되는지, 아니면 보낼 때마다 확인해야 하는지.
- 가입하지 않은 사람의 AI 동의는 서버에 남기지 않고 **브라우저에만** 기억한다(해당 탭이 열려 있는 동안). **[확인 필요]** 동의 입증 책임과 충돌하지 않는지(법 제22조제3항의 입증 책임은 동의 없이 처리하는 경우에 관한 것이지만, 동의를 받았다는 사실도 우리가 입증해야 할 수 있다).
- 화면 문구와 처리방침의 항목·기간·업체명은 한 파일(예: `config/privacy-facts.json`)에서 함께 가져오게 하면 서로 어긋나지 않는다. **[가정]** 구현 때 정한다.
- 공개 전 검사: 390px 화면에서 체크 상자와 버튼이 겹치지 않는지, 동의 문구가 본문보다 작지 않은지 숫자로 확인한다(`verify-visual`).
